# Data format

Every session you record gets its own folder in `data/`. Open the files at the
top first. The `replay/` folder is only needed to re-create a session (for
example, to render it as video).

```
data/
  sessions.csv                                  one line per session: start here (generated, see below)
  splits.json                                   which sessions are train / val / test (made by processing/make_splits.py)
  2026-10-01_14-03-22_player1_soft_aim_ab12cd/   one folder per session
    summary.json                                who played, cheat + label, settings, results
    frames.csv                                  one row per frame (60 per second)
    targets.csv                                 one row per target
    replay/                                     exact data to re-create the session
      frames.csv
      targets.csv
```

Folder names are `date_time_player_cheat_id`, so they sort in the order they were recorded.

---

## `sessions.csv`: every session at a glance

Generated by `python processing/sessions.py`, which also prints how many
sessions there are per cheat type and player. It's rebuilt from the session
folders rather than added to after each session, so two people recording into
one shared Drive folder can't overwrite each other. Re-run the command to update
it, and don't edit it by hand.

| Column | Meaning |
|---|---|
| `folder` | The session's folder in `data/` |
| `recorded_at` | Date and time the session ended |
| `player` | Who played (`bot` for snap) |
| `cheat` | `clean`, `soft_aim`, `strong_aim`, `wallhack`, `soft_aim+wallhack`, `strong_aim+wallhack` or `snap` |
| `label` | **0 = clean, 1 = cheating**. This is what the detection models try to predict |
| `aim_cheat_level` | How strong the aim cheat was, from 0.0 (weakest) to 1.0 (strongest). Blank if no aim cheat |
| `wallhack_level` | Same for the wallhack. Blank if the wallhack was off |
| `duration_s` | Session length in seconds |
| `targets_appeared` / `targets_hit` | How many targets spawned / were shot |
| `accuracy_pct` | Hits ÷ shots × 100 |
| `median_time_to_kill_ms` | Typical time from a target appearing to being shot |

## `summary.json`: one session in detail

- `session`: folder, when, player, and the cheats:
  - `cheat`: the combination, e.g. `strong_aim+wallhack`
  - `aim_cheat`: `none`, `soft_aim`, `strong_aim` or `snap`
  - `wallhack`: `true` / `false`
  - `label`: 0 = clean, 1 = cheating (spelled out in `label_meaning`)
- `results`: the scores above, plus targets expired, shots and missed shots
- `cheat_strength`: how strong each cheat was this session. Strength is random
  every session and hidden from the player. Empty for clean sessions.
  - `aim_cheat`: `level` (0.0 weakest to 1.0 strongest), plus the knob values that
    level produced. Soft aim: `strength`, `radius_px`. Strong aim: `strength`,
    `radius_px`, `your_direction_pct`. Snap: `delay_ms`
  - `wallhack`: `level`, plus `warning_ms` (how early the ring showed where the
    next target would appear) and `linger_ms` (how long it stayed on a new target)

  The ranges each level maps onto are in `STRENGTH_RANGES` at the bottom of `cheats.py`.
- `settings`: the same for every session except sensitivity:
  `sensitivity_px_per_count`, `session_length_s` (60), `spawn_gap_min_ms` (300)
  and `spawn_gap_max_ms` (1200)
- `seed`: the random seed, which reproduces the same target positions and timings

## `frames.csv`: what happened each frame

One row per game frame (the game runs at 60 frames per second). Positions are
in screen pixels: (0, 0) is the top-left corner, x grows to the right, y grows
downward. The play area is 800 × 600, below a 50 px top bar.

| Column | Meaning |
|---|---|
| `frame` | Frame number, starting at 0 |
| `time_s` | Seconds since the session started |
| `move_x_px`, `move_y_px` | How far the crosshair moved this frame, **after** any aim cheat changed it |
| `crosshair_x_px`, `crosshair_y_px` | Where the crosshair is after moving |
| `shot` | Blank = didn't shoot, `hit` = shot hit the target, `miss` = shot hit nothing |
| `target_id` | Which target this row describes. There is only ever one: either on screen, or waiting to appear |
| `target_visible` | **1** = on screen, **0** = hidden (the gap before it appears) |
| `target_x_px`, `target_y_px` | Target center, even while hidden |
| `target_distance_px` | Crosshair → target center |
| `target_size_px` | Current radius, while visible. Targets grow from 0 to 30 px, then shrink |
| `target_age_ms` | How long it has been visible |
| `target_appears_in_ms` | While hidden: how long until it appears |

When `target_visible` is 0, the target's position is **hidden information**: a
clean player can't know it, but the game does (like a game server knowing where
enemies are). A wallhack user moves toward the target before it appears, so
`target_distance_px` shrinking while `target_visible` is 0 is a wallhack
giveaway that only the frame data, not the video, can see directly.

## `targets.csv`: every target

| Column | Meaning |
|---|---|
| `target_id` | Matches `target_id` in `frames.csv` |
| `x_px`, `y_px` | Target center |
| `appeared_at_s` / `ended_at_s` | When it became visible / was hit or disappeared |
| `outcome` | `hit`, `expired` (shrank away unshot), or `on_screen_at_end` |
| `time_to_kill_ms` | Only for hits: time from appearing to being shot |
| `time_on_screen_ms` | How long it was visible, whatever the outcome |
| `size_when_ended_px` | Radius when shot (smaller = shot earlier in its growth) |
| `crosshair_distance_when_appeared_px` | How far away the crosshair was at the moment it appeared. Near 0 means the player was already waiting on the spot (a wallhack sign) |

## `replay/`: exact data to re-create a session

You don't need these files to analyse a session. They hold the exact values,
without rounding, that `processing/render_video.py` uses to replay the session
frame by frame with Tim's own game code.

### `replay/frames.csv`

| Column | Meaning |
|---|---|
| `frame`, `time_s` | Frame number and time (6 decimals) |
| `frame_length_s` | How long this frame lasted |
| `mouse_counts_x`, `mouse_counts_y` | Whole mouse counts applied this frame (pixels = counts × sensitivity) |
| `crosshair_x`, `crosshair_y` | Exact crosshair position |
| `clicked` | 1 if a shot was fired this frame |

### `replay/targets.csv`

| Column | Meaning |
|---|---|
| `target_id`, `x`, `y` | Target identity and center |
| `decided_frame`, `decided_time_s` | When the game picked its position (the moment the previous target was hit or expired). The wallhack can see it from here on |
| `scheduled_spawn_time_s` | When it was due to appear |
| `spawn_frame` | First frame it is visible on |
| `end_frame` | Frame it was hit or expired on (it's **not** drawn on that frame). Blank if still on screen at the end |
| `outcome` | `hit`, `expired`, `on_screen_at_end`, or `not_spawned` (decided but the session ended first) |

Target sizes aren't stored. Tim's targets grow and shrink by a fixed amount
each frame, so the size on any frame is re-created exactly by calling Tim's
`Target.update()` once per frame from `spawn_frame` on.
